# Создание навыка библиотеки

Используй системный `skill-creator` для каркаса и `writing-for-agents` для
краткого исполняемого текста. Полностью прочитай
[`references/library-skill-contract.md`](references/library-skill-contract.md).

## Сначала зафиксировать поведение

1. Определи профиль: `single-library`, `catalog-router` или
   `artifact-retrieval`.
2. До редактирования сохрани копию, SHA-256 файлов, interface/policy, доступные
   инструменты, версии, каталоги и профильные инварианты.
3. Запусти одинаковый baseline-вопрос независимым агентом в свежем контексте;
   сохрани обезличенные оценки ответа и источников, названия и длительность
   MCP-вызовов. Не сохраняй сырые ответы MCP, приватные тексты или конфигурацию.
4. Для artifact-профиля отдельно зафиксируй list/get, статусы, формат ответа,
   writer, SHA-256, коллизии и параллельное скачивание. Не упрощай их до
   обычного поиска.

## Изменить минимально

- Опубликованный навык до поиска проверяет свою версию по
  [`references/skill-update.md`](references/skill-update.md). Версия пакета
  задаётся в `metadata.version`; `scripts/build-library-skills.py` в корне
  проекта собирает автономные ZIP и каталог сайта из опубликованных навыков.
- Поиск документации начинается через нативный `lib-docs`; проверка
  обновления пакета выполняется отдельно.
- Обычный профиль делает один объединённый `search_docs(limit=5)` на библиотеку
  и отвечает сразу. Только для одной явно непокрытой самостоятельной части
  допустим ровно один уточняющий поиск; максимум — два поиска на библиотеку.
- Независимые библиотеки и retrieval-вызовы выполняются параллельно.
- `list_libraries` используется только после реальной ошибки прямого вызова.
- Проверяй инструкции по фактически доступным read-only инструментам. Отсутствие
  `fetch_url` не разрешает переход к административному `lib-docs-full`.
- Каталоги и языковая политика живут в одном YAML; `SKILL.md` остаётся коротким
  маршрутизатором.
- Artifact-профиль сохраняет свой поисковый бюджет и весь прежний tool surface.

## Проверить

1. Запусти системный `quick_validate.py` и
   `scripts/validate_library_skill.py PATH`.
2. Повтори baseline и профильную матрицу в свежих контекстах с теми же моделью,
   effort, сервером и prompt.
3. Прими изменение только если старые PASS сохранены, существенные положения и
   специальные возможности не потеряны, число MCP-вызовов не выросло, медианное
   время не хуже и улучшился хотя бы один показатель.
4. При регрессии восстанови конкретный навык, найди минимальную причину и повтори
   затронутый сценарий, затем всю профильную матрицу.

Навык готов только после сравнительного PASS. Собственное чтение `SKILL.md` не
заменяет blind live-тест.
