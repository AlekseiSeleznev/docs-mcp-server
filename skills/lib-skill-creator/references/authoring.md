# Структура и выпуск lib-скилла

## Создать или перенести

Найди корень целевого проекта и прочитай его инструкции. В docs-mcp-server
источники находятся в `skills/`, сценарии сборки — в `scripts/`. Сравни целевой
профиль с действующим аналогом; скопируй только нужные возможности, не его
название, предметную область, версию или старый `release.json`.

- `SKILL.md`: frontmatter с `name` и `description`; для публикуемого пакета
  `metadata.version` в формате `"X.Y.Z"`. Имя навыка `lib-*` и техническое имя
  библиотеки MCP — разные значения. Версия пакета навыка также отличается от
  версии сервера (например, 3.3.0) и версии документации.
- `agents/openai.yaml`: интерфейс, фактическая зависимость `lib-docs` и политика
  вызова. Сохраняй существующие настройки; при новом навыке автоматический выбор
  разрешён по умолчанию. В Claude встроенные инструкции обращаются к коннектору
  `lib`; отдельную политику ручного вызова переноси в формат соответствующего
  клиента, если исходный навык действительно ручной.
- `references/indexed-pages.md`: автономная копия общей справки этого навыка,
  ссылка на неё с условием чтения в `SKILL.md`.
- Для `catalog-router`: один авторитетный YAML с точными именами, областью,
  версиями и правилами выбора. В 1С/SAP проекта используй существующий главный
  каталог и его проекции; не редактируй производные списки как независимые.
- Для `artifact-retrieval`: сохраняй профильный каталог и bundled writer,
  доступность исходников, раздельные Matched/Related и прежнюю политику скачивания.
- Для публичного автообновления: `references/skill-update.md` и
  `scripts/update-skill.py`. В проекте их канонические источники — справка этого
  навыка и `scripts/update-library-skill.py`. Общий updater узнаёт имя пакета из
  frontmatter; новая библиотека не возникает от переименования навыка.

Проверь ссылки на локальные файлы из `SKILL.md`, наличие всех ресурсов и запуск
валидатора абсолютным путём из другой рабочей папки. Локальные скрипты не должны
искать ресурсы относительно случайного текущего каталога.

## Подготовить выпуск

Этот раздел применяется, когда пользователь поручил выпуск или установку.
Изменение автора навыков само по себе не требует пересборки всех опубликованных
пакетов. Общая справка автора становится частью прикладных пакетов при следующем
их выпуске; изменение уже опубликованного пакета требует новой версии.

1. Для меняющегося публичного навыка увеличь `metadata.version`. Если новый
   навык должен появиться на сайте, добавь его в публичный выбор установки.
   Частные и ручные проектные навыки остаются вне публичного каталога.
2. Из найденного корня docs-mcp-server запусти `scripts/build-library-skills.py`.
   Он выбирает публичные навыки по сайту, копирует общие ресурсы и собирает
   `release.json`, ZIP и `skills/md/skill-versions.json`. Используй фактическую
   реализацию сборщика как источник состава пакета; версии общего файла,
   встроенные в меняющиеся пакеты, должны соответствовать выпуску.
3. Проверь содержимое ZIP, все хеши, соответствие имени/версии и установку из
   прежнего пакета с сохранением `agents/openai.yaml` и пользовательских файлов.
   Для новой публикации проверь чистую установку. Пакет должен работать без
   соседней папки автора навыков. Повторная проверка обновления возвращает
   `current`; локальные изменения не затираются автоматически.
4. Синхронизируй порученные локальные копии, сохраняя symlink, interface/policy,
   пользовательские файлы и исключая `__pycache__`. Изменённое поведение должно
   совпадать с каноническим источником; клиентские настройки могут отличаться.
5. При порученной публикации сначала сохрани предыдущий выпуск; опубликуй
   согласованные HTML, ZIP и каталог. Проверь реальные HTTPS-хеши и установку
   опубликованного пакета. Проверка локальных файлов не доказывает публикацию.

`lib-skill-creator` — авторский инструмент, а не одна из публичных библиотек.
Он не попадает в каталог автообновления, пока явно не добавлен туда отдельным
выпуском. Сборка, установка, Git и публикация — отдельные проверяемые результаты;
сообщай только те из них, которые фактически выполнены.
