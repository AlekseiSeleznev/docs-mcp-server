# Навигация и чтение индексированных страниц

Используй read-only `lib-docs` (в Claude — коннектор `lib`) в уже выбранных
библиотеках и версиях. Правила выбора книг и `find_version` из `SKILL.md`
действуют до чтения. Эти маршруты заменяют начальный поиск, когда он не нужен:

- Обычный предметный вопрос: один `search_docs(limit=5)` по правилам профиля.
  Если найденных сведений достаточно, отвечай сразу без дополнительных вызовов.
- Пользователь дал известный индексированный URL или точный путь страницы:
  `read_page` с `pathOrUrl` из запроса или результата MCP.
- Нужен список страниц или неизвестен точный путь: `list_pages` с `limit=20`.
  `contains` фильтрует подстроку URL, а не смысл текста. Выбери подходящую
  страницу по возвращённым URL и заголовкам, затем вызови `read_page`.
  Следующую порцию списка запрашивай только при необходимости через `offset`.
- Поисковый фрагмент оборвал нужное условие, таблицу или пример: прочитай ту же
  страницу через `read_page`, не трать уточняющий поиск на соседний фрагмент.

В `read_page` передавай тот же `library`, разрешённую `version` и точный URL.
Продолжай только пока не покрыт вопрос. В текущем текстовом ответе MCP 3.3.0
смещение дано в подсказке `To continue, call read_page again with startChunk: N.`:
передай указанный `N` следующим `startChunk`, сохранив библиотеку, версию и URL.
`nextChunk` — внутреннее поле сервиса; отдельного JSON-поля в MCP-ответе может
не быть. Если клиент действительно возвращает структурированное `nextChunk`,
используй его значение. Для явно запрошенной полной страницы продолжай до конца
по фактической подсказке/метаданным клиента; отсутствие JSON-поля `nextChunk`
само по себе не означает конец. Не называй фрагмент полной страницей и не
вычисляй смещение самостоятельно. При повторении смещения остановись и сообщи
о сбое. Если признак продолжения неясен, отметь неполноту прочитанного.
При неоднозначном суффиксе уточни точный URL через `list_pages`, не выбирай
произвольное совпадение. Не перечисляй всю библиотеку для обычного вопроса.

Используй только инструменты, доступные в текущем MCP-клиенте. Если новых
инструментов нет, сообщи о необходимости обновить подключение MCP и используй
прежний ограниченный поиск. Не выдумывай вызовы и не переходи к `lib-docs-full`,
`fetch_url` или внешнему HTTP для обхода read-only доступа.

Источники и выводы подтверждаются прочитанным содержимым. Авторов и год бери
из метаданных той же страницы; уже полученные метаданные этой страницы можно
использовать без повторного поиска. Не добавляй вызовы ради оформления ссылки.
Внутренние пути не становятся публичными URL. Формат ответа из `SKILL.md`
сохраняется; footer учитывает библиотеки, для которых фактически вызваны
`search_docs`, `list_pages` или `read_page`, а в artifact-профиле также
`list_source_artifacts` и `get_source_artifact`. Один `find_version` не считается
чтением документации. Порядок библиотек — порядок первого такого вызова.

`read_page` возвращает индексированный текст, а не исходный файл. Правила
`list_source_artifacts`, `get_source_artifact`, Matched/Related, сохранения
байтов и проверки SHA-256 остаются прежними. Чтение страницы не заменяет
получение исходного документа по запросу пользователя.
