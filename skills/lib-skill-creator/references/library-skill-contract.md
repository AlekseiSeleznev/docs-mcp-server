# Контракт профилей `lib-*`

## Общее

- Все сведения читаются через `lib-docs`; внутренние пути, секреты и сырой MCP
  не попадают в ответ.
- Неоднозначность разрешается одним вопросом и нулём вызовов; без разделов,
  источников и footer.
- Версия разрешается через `find_version`, когда она запрошена или закреплена.
- Если выбран поиск, первый вызов использует `limit=5`; независимые вызовы
  выполняются параллельно. Для известной страницы действует маршрут чтения.
- `list_libraries` допустим только после реальной ошибки.
- Прямой ответ содержит только подтверждённые найденными фрагментами факты.
  Неподтверждённую часть обозначай прямо, без предполагаемого ответа с оговоркой.
- Ответ содержит `## По документации`, нумерованные пункты и одну строку
  `[Источник]` после каждого подтверждённого пункта. Несколько полных источников
  в этой строке разделяются ` | ` без повторения маркера. После заголовка нет
  предметных абзацев и источников вне нумерованных пунктов. Footer последней
  строкой перечисляет только реально использованные библиотеки.
- Подтверждённые рекомендации остаются внутри нумерованных пунктов; отдельный
  раздел рекомендаций не нужен.
- Для книжных SAP-источников авторов и год бери только из того же результата.
  Подпись `авторы:` сохраняется и для одного имени; отсутствующие поля опускаются.

## Чтение страниц

Общий маршрут задаёт `indexed-pages.md`. Известный URL читается через
`read_page`; навигация использует `list_pages`, затем точную страницу.
Оборванный результат поиска дополняется чтением той же страницы. Обычный
достаточный ответ не требует дополнительных вызовов. Версии, области,
источники и footer действуют и без поиска; исходные файлы получает прежний
artifact-маршрут. Для новых сценариев отдельно проверяются продолжение,
неоднозначность пути и отсутствие инструментов у старого клиента.

## `single-library`

Одна техническая библиотека. Один объединённый `search_docs` на вопрос; для
одной явно непокрытой самостоятельной части допустим ровно один уточняющий
поиск. Непокрытая область не подключает другую библиотеку.

## `catalog-router`

Маршрутизация определяется одним авторитетным YAML. Выбирается минимальный набор
библиотек; по каждой выполняется один объединённый поиск и при необходимости
ровно одно уточнение непокрытой самостоятельной части. Независимые библиотеки
обрабатываются параллельно. Проекции каталогов не дублируют правила.

## `artifact-retrieval`

Сохраняются `list_source_artifacts`, `get_source_artifact`, Matched/Related,
статусы доступности, invocation policy, каталог назначения, bundled writer,
JSONL, SHA-256, проверка формата, защита от коллизий, профильный поисковый бюджет
и параллельное скачивание. Информационный запрос не получает байты.

## Приёмка

- Статические валидаторы подтверждают структуру, ссылки и комплектность;
  рабочие MCP-аргументы и качество ответа проверяются поведением.
- Для доработки сравниваются одинаковые запросы, модель, effort и сервер:
  старые PASS и существенные факты сохраняются. Раздельно оцениваются смысл,
  источники, оформление, область, версии и число вызовов.
- Для оптимизации число вызовов не растёт, медианное время не хуже и хотя бы
  один показатель улучшается. Для исправлений и новых возможностей требуется
  доказательство корректности; вызовы для необходимого дочитывания считаются
  отдельно. Случайная разница разовых задержек не доказывает ускорение.
- У нового навыка нет старой версии: проверяются заранее определённые запросы,
  отрицательные случаи и границы его собственного профиля.
- Для artifact-профиля проверяются list/get, формат, writer, коллизии и SHA-256.
- Непроверенные смысл или оформление остаются NOT_CHECKED даже при успешном
  поиске. Поведенческий PASS требует оценки сформированного ответа.
