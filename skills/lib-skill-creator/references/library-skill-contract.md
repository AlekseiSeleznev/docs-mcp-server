# Контракт профилей `lib-*`

## Общее

- Все сведения читаются через `lib-docs`; внутренние пути, секреты и сырой MCP
  не попадают в ответ.
- Неоднозначность разрешается одним вопросом и нулём вызовов.
- Версия разрешается через `find_version`, когда она запрошена или закреплена.
- Первый поиск использует `limit=5`; независимые вызовы выполняются параллельно.
- `list_libraries` допустим только после реальной ошибки.
- Ответ содержит проверяемые источники и footer с реально использованными
  библиотеками.

## `single-library`

Одна техническая библиотека. Один объединённый `search_docs` на вопрос; для
одной явно непокрытой самостоятельной части допустим ровно один уточняющий
поиск. Непокрытая область не подключает другую библиотеку.

## `catalog-router`

Маршрутизация определяется одним авторитетным YAML. Выбирается минимальный набор
библиотек; по каждой выполняется один объединённый поиск и при необходимости
ровно одно уточнение непокрытой самостоятельной части. Независимые библиотеки
обрабатываются параллельно. Проекции каталогов не дублируют правила.

## `artifact-retrieval`

Сохраняются `list_source_artifacts`, `get_source_artifact`, Matched/Related,
статусы доступности, invocation policy, каталог назначения, bundled writer,
JSONL, SHA-256, проверка формата, защита от коллизий, профильный поисковый бюджет
и параллельное скачивание. Информационный запрос не получает байты.

## Приёмка

- `quick_validate.py` и профильный валидатор проходят.
- Старый и новый варианты тестируются одинаковыми prompt/model/effort/server.
- Ни один старый PASS не становится FAIL; ответы не теряют существенные факты.
- Число вызовов не растёт, медианное время не хуже, минимум один показатель
  улучшается.
- Для artifact-профиля тестовые файлы совпадают по SHA-256.
