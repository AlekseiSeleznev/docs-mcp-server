# Документация для разработки 1С

Используй только read-only MCP `lib-docs`. Всегда отвечай человеку обычным
понятным текстом по формату ниже.

Полный перечень доступных книг, версий, названий и технических признаков
находится в [`references/libraries.yaml`](references/libraries.yaml). Это
единственный источник маршрутизации. Перед поиском найди в нём подходящие
записи; не заменяй отсутствующую книгу похожей.

## Выбор книг

1. Сначала учитывай явное название технологии, библиотеки, книги, техническое
   имя `onec_*` и версию. Явное название имеет приоритет над ключевыми словами.
2. Если явного названия нет, выдели техническую потребность: объект или API,
   действие, контекст выполнения, версия и ожидаемое поведение. По ней выбери
   минимальный достаточный набор записей каталога.
3. Общий вопрос без технического объекта уточни одним коротким вопросом и до
   ответа не вызывай MCP.
4. Вопрос только о выполнении бизнес-операции в прикладной конфигурации относится
   к `lib-1c-cons`. Не подменяй прикладное руководство документацией платформы.
5. Для пересечений используй несколько книг только когда нужны разные виды
   подтверждения. Типичные случаи:
   - API платформы и нормативный стандарт — платформа + стандарты;
   - запрос внутри СКД — язык запросов + сложные отчёты;
   - изменение формы через расширение — расширения + интерфейс;
   - облачная интеграция — интеграция + облако;
   - API БСП с платформенными объектами — БСП + платформа;
   - определение термина и его поведение — глоссарий + профильная книга.
6. Живой код и метаданные проекта определяют, какие объекты реально существуют.
   Документация подтверждает API, поведение и ограничения. Не выдумывай имена
   объектов или реквизитов конкретной конфигурации.

## Версии и поиск

- Первым внешним действием вызывай нативный `lib-docs`: не проверяй
  resources/templates, MCP-конфигурацию и не используй shell, Python или ручной
  HTTP. Каталог прочитай один раз. Независимые вызовы для разных библиотек
  запускай параллельно.
- При явной версии сначала вызови `find_version`. Для semantic-версий требуется
  точное совпадение; отсутствующую версию нельзя заменять соседней.
- Значение версии с `version_kind: snapshot` — дата снимка документации, а не
  версия платформы или конфигурации.
- Без явной версии используй последнюю доступную версию выбранной библиотеки.
- В аргумент `library` копируй техническое имя из каталога дословно; не меняй
  подчёркивания на дефисы и не выводи имя из отображаемого названия.
- Сделай один начальный `search_docs` на библиотеку с `limit: 5`, объединив в
  запросе все назначенные ей самостоятельные части. Проверь все результаты и
  отвечай сразу. Только для одной явно непокрытой части допустим ровно один
  уточняющий поиск с `limit: 5`; максимум — два поиска на библиотеку.
- Утверждай API, ограничения и рекомендуемые действия только по найденным
  фрагментам. Не уточняй поиск ради формулировки, источника или метаданных.
- Кодовый пример должен использовать только подтверждённые API. Имена объектов
  проекта показывай как заменяемые примеры и отдельно предупреждай проверить их
  в метаданных.
- Только после реальной ошибки прямого вызова один раз вызови `list_libraries`. Если
  библиотека, точная версия или MCP недоступны, скажи об этом прямо.

## Формат ответа

Всегда отвечай в этом пользовательском формате, даже если вопрос задаёт другой
ИИ-агент.

1. Начни с прямого ответа в одном-трёх предложениях без заголовка.
2. Добавь раздел `## По документации`.
3. Каждый подтверждённый аспект оформи отдельным пунктом
   `### N. Краткий заголовок`. Код помещай в обычный fenced-блок внутри пункта.
4. После подтверждённого пункта оставь пустую строку и добавь ровно одну строку:
   `[Источник] {Book}; {Breadcrumb}; <{ITS URL}>`.
   Используй доступные название и видимый раздел; публичный URL добавляй только
   когда он присутствует в результате. Несколько источников
   разделяй ` | ` после одного маркера `[Источник]`.
5. Неподтверждённую часть вынеси в отдельный нумерованный пункт без источника и
   прямо напиши: `Подтверждение не найдено.` Не превращай её в код или совет.
6. Заверши ответ последней строкой
   `[Использованы библиотеки: onec_name, ...]` в порядке первого поиска. Если
   поиска не было, напиши `[Использованы библиотеки: нет]`.

Задача завершена, когда ответ понятен человеку, каждый технический факт и API
подтверждены источником, а непроверенные сведения явно отделены.
