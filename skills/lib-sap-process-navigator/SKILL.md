# SAP Process Navigator

Подтверждай сведения через read-only MCP `lib-docs`. Работай только с библиотекой `sap_process_navigator` и не расширяй область без указания пользователя.

## Определить область

- До любого вызова инструмента проверь предметный текст пользователя. Не считай путь к этому `SKILL.md`, загрузку навыка или служебную инструкцию прочитать его явным указанием продукта.
- Явное название SAP Process Navigator, SAP Best Practices, `$lib-sap-process-navigator` или техническое имя `sap_process_navigator` однозначно задаёт библиотеку. Точный process ID, Process Card, Source Release, scope item и связка SAP Cloud ALM с test script также задают область, если контекст относится к процессам SAP.
- Для общих терминов BPMN, закупка, продажа, производство, склад, активы или финансы без однозначного контекста SAP Process Navigator задай ровно один короткий уточняющий вопрос. Выведи только вопрос. До ответа не вызывай инструменты, не выбирай продукт, не формируй разделы и footer. Это правило имеет приоритет над поиском.
- Если пользователь явно ограничил поиск этой библиотекой, сохрани границу. Непокрытую часть отметь отдельно; не подменяй её сведениями из другого продукта или библиотеки SAP.
- Никогда не вызывай `find_version`, `search_docs`, `list_source_artifacts`, `get_source_artifact` или `list_libraries` для другой библиотеки. Если весь запрос вне области SAP Process Navigator, не вызывай инструменты и оформи непокрытый пункт.
- Библиотека покрывает совместимые версии `2025.x`. Другие поколения SAP Best Practices не подменяй содержимым 2025.x.

## Найти подтверждение

1. Первым вызови `find_version` с `library="sap_process_navigator"` и `targetVersion="2025.x"`. Если пользователь указал совместимую 2025.x версию, передай её как target. Если найденная версия несовместима с запрошенной, остановись до `search_docs`, оформи несовместимость и запроси разрешение использовать найденную версию. Во все дальнейшие поиски и списки передавай найденную версию.
2. Русский предметный запрос преобразуй в один точный английский Search Query. Используй точные английские термины SAP для process name, process ID, Line of Business, roles, prerequisites, tasks, events, gateways, test steps и expected results. Не добавляй перевод, русские дубликаты или машинно переведённый материал в индекс.
3. Объедини независимые части запроса в один начальный поиск. Первый и единственный начальный `search_docs` выполни с `limit=5`. Изучи все результаты, включая их Process Card, Matched Artifacts и Related Artifacts, до следующего вызова.
4. Если подтверждение неполное, уточни английский Search Query не более двух раз. Абсолютный предел на весь пользовательский запрос — три `search_docs` в библиотеке `sap_process_navigator`, а не три на каждый пункт. После третьего поиска остановись. Для повторов используй только `limit=5` или `limit=10`; `limit=10` допустим лишь после оценки первого результата.
5. Считай Matched Artifacts прямым основанием найденного Search Result. Related Artifacts принадлежат тому же процессу, но сами не подтверждают совпадение. Удали повторы по `artifactId` и не смешивай эти группы.
6. Показывай `Downloaded`, `Missing` и `ExternalUnresolved` честно. Для `Missing` и `ExternalUnresolved` не обещай файл и не пытайся получить его байты. Если Related Artifacts усечены, сообщи об этом и при реальной необходимости вызови `list_source_artifacts` для выбранных process ID, библиотеки и версии.
7. Не получай Source Artifact для обычного информационного ответа. Переходи к исходному файлу только когда пользователь прямо просит файл либо задачу невозможно надёжно выполнить без точных исходных байтов.
8. Когда исходник нужен, сначала выбери доступную запись из Matched Artifacts или результата `list_source_artifacts`, затем вызови `get_source_artifact` только с непрозрачным `artifactId`. Допустим также read-only `resources/read` по уже возвращённому `sap-artifact` resource link. Не принимай от пользователя путь сервера, абсолютный путь, `file://`, storage key или произвольный URI вместо `artifactId`.
9. Никогда не вызывай `fetch_url`, Chromium, browser, инструменты записи или удаления. Не используй локальный или серверный файловый путь как обход read-only artifact retrieval.
10. При ошибке доступности один раз вызови `list_libraries` только для диагностики. Не подменяй отсутствующую библиотеку, версию или артефакт другой библиотекой.

Первоисточник — официальная библиотека SAP Best Practices for SAP S/4HANA Cloud Private Edition в `sap_process_navigator`. Существенные утверждения основывай только на английских Search Results. Русский ответ является изложением найденного подтверждения, а не переведённой копией индекса. Если основания нет, прямо напиши, что подтверждение в выбранной библиотеке не найдено.

## Сформировать ответ

1. Начни с прямого вывода на русском языке в 1–3 предложениях без заголовка.
2. Добавь точный заголовок `## По документации`.
3. Оформи подтверждённые и непокрытые положения последовательными пунктами `### 1.`, `### 2.` и далее только внутри этого раздела. Не смешивай непокрытое положение с подтверждённым пунктом.
4. После текста каждого подтверждённого пункта оставь пустую строку и отдельную строку источника:
   `[Источник] {Официальная публикация}; {Process ID, Process Name или раздел}; <{публичный URL}>`
5. В одном подтверждённом пункте литерал `[Источник]` используй ровно один раз — только в начале строки источника. Никогда не повторяй `[Источник]` после `|`. Несколько источников перечисляй в той же строке через ` | `; каждый фрагмент по обе стороны разделителя обязан быть полным источником с собственными названием публикации, разделом и, если подтверждён, публичным URL. Не ставь после `|` отдельный URL или раздел. Если библиотека вернула только внутренний путь, не показывай `file://`, не выдумывай URL и закончи источник после раздела без поясняющей фразы.
6. Когда Search Result содержит Source Artifacts, после соответствующего пункта добавь краткие списки `Matched Artifacts` и `Related Artifacts`. Для каждого элемента укажи имя, тип, статус и `artifactId`; недоступный статус поясни без попытки retrieval. Не представляй Related Artifact как доказательство найденного утверждения.
7. Если исходный файл действительно получен, отдельно укажи выбранный артефакт, его `artifactId`, предложенное имя и проверенный тип. Не показывай base64, сырые байты, внутренний путь или storage key.
8. Если нужен синтез, добавь `## Выводы и рекомендации` с нумерованными рекомендациями, основанными только на подтверждённых пунктах.
9. Последней строкой без текста после неё выведи `[Использованы библиотеки: sap_process_navigator]`, если `search_docs` был вызван хотя бы один раз. Если поиск не вызывался из-за неоднозначности, неподдерживаемой области или несовместимой версии, используй `[Использованы библиотеки: нет]`; при одном уточняющем вопросе до поиска footer не добавляй.

Даже при недоступности MCP, отсутствии версии или подтверждения сохраняй эту структуру: помести состояние в `### 1.`, не добавляй выдуманный `[Источник]` и заверши точным footer.

Не показывай даты снимков, `Snapshot date`, `undefined`, внутренние пути, приватные адреса и сырые ответы MCP. Сохраняй официальные английские имена процессов, ролей, шагов и артефактов внутри русского ответа.
