# SAP Process Navigator

Подтверждай сведения через read-only MCP `lib-docs`. Работай только с библиотекой `sap_process_navigator` и не расширяй область без указания пользователя.

## Определить область

- До любого вызова инструмента проверь предметный текст пользователя. Не считай путь к этому `SKILL.md`, загрузку навыка или служебную инструкцию прочитать его явным указанием продукта.
- Явное название SAP Process Navigator, SAP Best Practices, `$lib-sap-process-navigator` или техническое имя `sap_process_navigator` однозначно задаёт библиотеку. Точный process ID, Process Card, Source Release, scope item и связка SAP Cloud ALM с test script также задают область, если контекст относится к процессам SAP.
- Для общих терминов BPMN, закупка, продажа, производство, склад, активы или финансы без однозначного контекста SAP Process Navigator задай ровно один короткий уточняющий вопрос. Выведи только вопрос. До ответа не вызывай инструменты, не выбирай продукт, не формируй разделы и footer. Это правило имеет приоритет над поиском.
- Если пользователь явно ограничил поиск этой библиотекой, сохрани границу. Непокрытую часть отметь отдельно; не подменяй её сведениями из другого продукта или библиотеки SAP.
- Никогда не вызывай `find_version`, `search_docs`, `list_source_artifacts`, `get_source_artifact` или `list_libraries` для другой библиотеки. Если весь запрос вне области SAP Process Navigator, не вызывай инструменты и оформи непокрытый пункт.
- Библиотека покрывает совместимые версии `2025.x`. Другие поколения SAP Best Practices не подменяй содержимым 2025.x.

## Найти подтверждение

1. Первым вызови `find_version` с `library="sap_process_navigator"` и `targetVersion="2025.x"`. Если пользователь указал совместимую 2025.x версию, передай её как target. Если найденная версия несовместима с запрошенной, остановись до `search_docs`, оформи несовместимость и запроси разрешение использовать найденную версию. Во все дальнейшие поиски и списки передавай найденную версию.
2. Русский предметный запрос преобразуй в один точный английский Search Query. Используй точные английские термины SAP для process name, process ID, Line of Business, roles, prerequisites, tasks, events, gateways, test steps и expected results. Не добавляй перевод, русские дубликаты или машинно переведённый материал в индекс.
3. Объедини независимые части запроса в один начальный поиск. Первый и единственный начальный `search_docs` выполни с `limit=5`. Изучи все результаты, включая их Process Card, Matched Artifacts и Related Artifacts, до следующего вызова.
4. Если подтверждение неполное, уточни английский Search Query не более двух раз. Абсолютный предел на весь пользовательский запрос — три `search_docs` в библиотеке `sap_process_navigator`, а не три на каждый пункт. После третьего поиска остановись. Для повторов используй только `limit=5` или `limit=10`; `limit=10` допустим лишь после оценки первого результата.
5. Считай Matched Artifacts прямым основанием найденного Search Result. Related Artifacts принадлежат тому же процессу, но сами не подтверждают совпадение. Храни эти группы раздельно при обосновании ответа; итоговый список артефактов является инвентарём выбранного процесса, а не доказательством совпадения.
6. Перед формированием итогового списка вызови `list_source_artifacts` один раз для каждого process ID, включённого в подтверждённый ответ. Читай записи из массива `structuredContent.artifacts`, даже если краткое текстовое представление результата не перечисляет их. Сгруппируй полный массив и удали повторы по `artifactId`. Учитывай `Downloaded`, `Missing` и `ExternalUnresolved` при выборе файла. Для `Missing` и `ExternalUnresolved` не обещай скачивание и не пытайся получить байты; в пользовательском списке замени эти технические статусы краткой пометкой `недоступен`.
7. Не получай Source Artifact для обычного информационного ответа. Переходи к исходному файлу только когда пользователь прямо просит файл либо задачу невозможно надёжно выполнить без точных исходных байтов.
8. Когда пользователь просит конкретный файл, выбери соответствующую доступную запись. Для запроса скачать все файлы или все документы выбери все доступные записи `Downloaded` из полного дедуплицированного результата `list_source_artifacts`; недоступные записи пропусти с кратким пояснением. Затем выполни раздел `Скачать исходник`. Не принимай от пользователя путь сервера, абсолютный путь, `file://`, storage key или произвольный URI вместо `artifactId`.
9. Получай байты только через `get_source_artifact`: используй blob из его embedded resource и не заменяй этот вызов на `resources/read`. Не вызывай `fetch_url`, Chromium или browser и не используй локальный либо серверный исходный путь как альтернативный источник файла.
10. При ошибке доступности один раз вызови `list_libraries` только для диагностики. Не подменяй отсутствующую библиотеку, версию или артефакт другой библиотекой.

## Скачать исходник

1. Сначала определи папку назначения. Для указанной пользователем папки разверни `~`, разреши относительный путь от текущей рабочей папки и нормализуй его до абсолютного. Без указанного пути начни с текущей рабочей папки и иди вверх до ближайшего каталога, содержащего хотя бы один маркер проекта: `.git`, `package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, `pom.xml`, `build.gradle` или `build.gradle.kts`; используй в нём `artifacts/sap-process-navigator/<Process ID>/`.
2. Если проектная папка не найдена, до получения исходных байтов задай один короткий вопрос о месте сохранения. Сообщи, что проектная папка не найдена, предложи рабочий стол как вариант по умолчанию и остановись до ответа.
3. Получи выбранные исходники только через `get_source_artifact`. Для двух и более артефактов запусти независимые retrieval-вызовы параллельно одним batch и дождись всех результатов.
4. После завершения всех retrieval-вызовов разреши путь `scripts/save-source-artifacts.mjs` относительно папки этого `SKILL.md` и запусти writer ровно один раз:
   `node <skill-dir>/scripts/save-source-artifacts.mjs --destination <абсолютная папка> --count <количество>`
   В Codex сразу используй интерактивный режим, дождись активной сессии и JSON `{"ready":true}`.
5. Для каждого результата передай writer одну полную строку JSONL с полями `suggestedFilename`, `blob`, `sizeBytes`, `sha256`, `mimeType`. Bundled writer сам отключает echo и canonical PTY mode, проверяет base64, размер, SHA-256, формат, существующие файлы и коллизии, затем сохраняет через `create-new` без временных файлов и удаления.
6. Считай fast path завершённым, когда writer вернул по одной записи с `status` и абсолютным `path` для каждого выбранного артефакта и завершился с кодом 0. При первом сбое writer допустим один повтор той же команды; повтор безопасно переиспользует уже проверенные файлы. После второго сбоя остановись и сообщи блокер.

Используй только этот fast path. Не генерируй inline Python или альтернативный writer, не запускай диагностические sleep/probe-команды и не повторяй проверки, уже выполненные bundled writer.

Первоисточник — официальная библиотека SAP Best Practices for SAP S/4HANA Cloud Private Edition в `sap_process_navigator`. Существенные утверждения основывай только на английских Search Results. Русский ответ является изложением найденного подтверждения, а не переведённой копией индекса. Если основания нет, прямо напиши, что подтверждение в выбранной библиотеке не найдено.

## Сформировать ответ

1. Для информационного ответа начни с прямого вывода на русском языке в 1–3 предложениях без заголовка.
2. Добавь точный заголовок `## По документации`.
3. Оформи подтверждённые и непокрытые положения последовательными пунктами `### 1.`, `### 2.` и далее только внутри этого раздела. Не смешивай непокрытое положение с подтверждённым пунктом.
4. После текста каждого подтверждённого пункта оставь пустую строку и отдельную строку источника:
   `[Источник] {Официальная публикация}; {Process ID, Process Name или раздел}; <{публичный URL}>`
5. В одном подтверждённом пункте литерал `[Источник]` используй ровно один раз — только в начале строки источника. Никогда не повторяй `[Источник]` после `|`. Несколько источников перечисляй в той же строке через ` | `; каждый фрагмент по обе стороны разделителя обязан быть полным источником с собственными названием публикации, разделом и, если подтверждён, публичным URL. Не ставь после `|` отдельный URL или раздел. Если библиотека вернула только внутренний путь, не показывай `file://`, не выдумывай URL и закончи источник после раздела без поясняющей фразы.
6. Если нужен синтез, добавь `## Выводы и рекомендации` с нумерованными рекомендациями, основанными только на подтверждённых пунктах.
7. Если выбранный процесс содержит Source Artifacts, в конце содержательной части добавь точный заголовок `## Артефакты` и сгруппируй полный результат `list_source_artifacts` по каталожному типу: `BPMN` — `Диаграммы процессов`, `Description` — `Описания процессов`, `Accelerator` — `Акселераторы`. Оставь названия групп обычным текстом без `[]`, заголовков Markdown и жирного выделения. Под каждой группой выведи маркированным списком для `Downloaded` только `suggestedFilename`, а для недоступной записи — её `name` и пометку `— недоступен`. Если в ответ вошло несколько процессов, внутри каждой группы сначала раздели записи обычной строкой `<Process ID> — <Process Name>`. Не выводи пустую группу, повторы, `Matched Artifacts`, `Related Artifacts`, технический статус, формат, размер или `artifactId` и не показывай `artifactId` в другом месте ответа.
8. Если сохранён один или несколько файлов, добавь строку `**Скачано**`, а ниже выведи по одной строке `имя файла → полный путь` в виде локальной Markdown-ссылки Codex: `- [имя файла](<абсолютный путь>)`. Используй одну ссылку на каждый сохранённый файл. Для любого локального target оберни target в `<...>`; пробелы оставь как есть и не экранируй круглые скобки внутри target. Когда запрос состоит только из скачивания — независимо от того, первый он или последующий, — не выводи разделы с документацией, выводами и инвентарём: ответь только блоком `**Скачано**`, кратко назови пропущенные недоступные записи при их наличии и добавь footer. Не показывай base64, сырые байты, внутренний путь источника, storage key, MIME, размер, SHA-256 или описание проверок.
9. Последней строкой без текста после неё выведи `[Использованы библиотеки: sap_process_navigator]`, если был вызван хотя бы один из `search_docs`, `list_source_artifacts` или `get_source_artifact`. Если инструменты библиотеки не вызывались из-за неоднозначности, неподдерживаемой области или несовместимой версии, используй `[Использованы библиотеки: нет]`; при одном уточняющем вопросе до поиска footer не добавляй.

Перед началом скачивания дай не более одного короткого обновления: `Сохраняю {количество} файлов в {папка}`. Не сообщай о восстановимой внутренней ошибке или безопасном повторе, пока действие продолжается без участия пользователя. Сообщи технический блокер только если безопасные попытки исчерпаны и без действия пользователя продолжить нельзя.

Даже при недоступности MCP, отсутствии версии или подтверждения сохраняй эту структуру: помести состояние в `### 1.`, не добавляй выдуманный `[Источник]` и заверши точным footer.

Не показывай даты снимков, `Snapshot date`, `undefined`, внутренние пути, приватные адреса и сырые ответы MCP. Сохраняй официальные английские имена процессов, ролей, шагов и артефактов внутри русского ответа.
