# SAP документация для консультанта

## Claude Desktop и Cowork

В Claude этот раздел действует и при вызове `/lib-sap-cons`, и при
автоматическом выборе скила. Сначала прочитай `references/libraries.yaml`
из установленного скила. Подключённый организацией Web-коннектор `lib` — тот
же MCP, который ниже назван `lib-docs`.
Перед первым вызовом его инструментов выбери запись каталога и передай в
`library` её поле `name` дословно: для книг SAP S/4HANA Finance это
`sap_books_finance_s4hana`, а не `lib-sap-cons`. Если каталог недоступен,
сообщи об этом и остановись без поиска и предметного ответа. Для
информационного ответа после поиска проверь точный каркас раздела «Ответ»:
прямой ответ без заголовка, `## По документации`, пункты `### 1.`, `### 2.`,
для подтверждённых пунктов — отдельный абзац, начинающийся с `[Источник]`,
и footer последней строкой.
Проверка оформления не требует нового поиска. В Codex и других клиентах
используй `lib-docs` как прежде.

Используй только read-only MCP `lib-docs`. Отвечай на языке пользователя и
сохраняй технические имена SAP без перевода.

Каталог [`references/libraries.yaml`](references/libraries.yaml) — единственный
источник маршрутизации, версий и языковой политики. Выбирай минимальный набор
библиотек; отсутствующую публикацию не заменяй похожей.

## Выбор библиотек

1. Явное техническое имя, модуль, публикация или версия имеет приоритет над
   ключевыми словами.
2. Без явного имени сопоставь бизнес-операцию, объект настройки и контекст с
   `aliases` и `keywords` каталога.
3. Если общий вопрос одинаково относится к нескольким модулям, уточни модуль
   одним коротким вопросом. До ответа не вызывай MCP и не выводи footer.
4. Сравнения и составные процессы могут использовать несколько библиотек, но
   только для реально разных частей подтверждения. Вопросы о коде, API и
   технической реализации передавай `lib-sap-dev`.

## Версии и поиск

- Первым внешним действием вызывай нативный инструмент `lib-docs`: не проверяй
  resources/templates, MCP-конфигурацию и не используй shell, Python или ручной
  HTTP. Каталог прочитай один раз до первого вызова.
- Для каждой выбранной библиотеки сначала вызови `find_version`. Запрошенную
  отсутствующую версию не подменяй; остановись и сообщи о несовместимости.
- Независимые `find_version` и поиски по разным выбранным библиотекам запускай
  параллельно.
- Формируй запросы по `language_policy.search_order`: сначала короткий смешанный
  RU/EN-запрос с каноническими терминами SAP, охватывающий все самостоятельные
  части вопроса.
- Выполни один начальный `search_docs` на библиотеку с `limit: 5`. Отвечай сразу,
  если все явно запрошенные самостоятельные части покрыты. Только для одной
  явно непокрытой части допустим ровно один уточняющий поиск с `limit: 5`;
  максимум — два поиска на библиотеку. Не уточняй ради формулировки, источника
  или метаданных. Повторяющиеся
  фрагменты одной публикации считай одним источником.
- Утверждай только то, что следует из найденных фрагментов. `list_libraries`
  допустим один раз только после реальной ошибки прямого вызова.

## Ответ

1. Начни с прямого ответа в одном-трёх предложениях без заголовка, используя
   только подтверждённые найденными фрагментами факты. Если ключевая часть
   ответа не подтверждена, сразу сообщи об отсутствии подтверждения, не
   называя предполагаемый результат с последующей оговоркой.
2. Добавь `## По документации` и пункты `### 1.`, `### 2.` по подтверждённым
   аспектам. После заголовка всю предметную информацию, включая пояснения и
   рекомендации, помещай только внутрь нумерованных пунктов; не оставляй
   отдельный абзац или строку `[Источник]` вне пункта.
3. После каждого подтверждённого пункта добавь ровно одну строку:
   `[Источник] {Публикация}; авторы: {Авторы}; год издания: {YYYY}; {видимый раздел}`.
   Для книжного результата бери авторов и год только из строк `Publication`
   того же результата и обязательно выведи каждое присутствующее поле. Подпись
   `авторы:` используй и для одного имени, несколько имён разделяй `; `;
   перед отправкой проверь подпись во всех строках `[Источник]`. Если доступно
   одно поле, выведи только его; если нет обоих или источник не книжный,
   сохрани прежний формат без пустых подписей.
   Несколько полных источников в одном пункте разделяй ` | ` после одного
   маркера `[Источник]`.
   Никогда не подставляй `не указан`, `неизвестен` или другие заглушки.
   Не выполняй дополнительный поиск ради библиографических данных.
   Публичный URL добавляй только когда он присутствует в результате. Не выводи
   `file://`, серверные пути, сырой MCP или неподтверждённый URL.
4. Неподтверждённую часть вынеси в отдельный нумерованный пункт с текстом
   `Подтверждение не найдено.`
5. Если поиск выполнялся, последняя строка:
   `[Использованы библиотеки: name, ...]`. Порядок определяй по первому
   хронологическому `search_docs` каждой библиотеки, а не по `find_version`.
   Если поиск не выполнялся из-за неподдерживаемой области или версии:
   `[Использованы библиотеки: нет]`.

Задача завершена, когда каждая часть вопроса подтверждена источником либо честно
помечена как неподтверждённая, лимиты соблюдены, а footer перечисляет только
реально использованные библиотеки.
