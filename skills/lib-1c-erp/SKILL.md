# Документация 1С:ERP

Подтверждай сведения через read-only MCP `lib-docs`. В Claude Desktop и Cowork
используй организационный Web-коннектор `lib` с теми же техническими именами
библиотек. Не заменяй его административным `lib-docs-full`.

## Выбор библиотеки

Прочитай [`references/libraries.yaml`](references/libraries.yaml) — единственный
каталог этого навыка. `onec_erp` подтверждает функциональность, настройки,
операции и поведение продукта; `onec_erp_implementation` — выбор и внедрение,
этапы, роли, обследование и управление проектом. Для составного вопроса выбирай
обе книги и проверяй их независимо. Методика внедрения не подтверждает поведение
прикладной конфигурации.

Явное название 1С:ERP или вызов `$lib-1c-erp` задаёт продукт. Для общего вопроса
про ERP без такого контекста задай ровно один короткий вопрос о продукте и
остановись без вызовов MCP, разделов и footer. Загрузка файла навыка сама по себе
не является выбором продукта. Не подменяй отсутствующую книгу похожей.

## Версии и поиск

1. Первым внешним действием используй нативный `lib-docs`; не проверяй
   resources/templates, конфигурацию MCP и не используй ручной HTTP.
2. При явной версии сначала вызови `find_version` для выбранной библиотеки.
   При несовместимости остановись до поиска и сообщи об отсутствии нужной
   версии. Без явной версии используй последнюю доступную.
3. Выполни один объединённый `search_docs` на библиотеку с `limit=5`.
   Независимые библиотеки проверяй параллельно; изучи все найденные фрагменты.
4. Если все части вопроса покрыты, отвечай сразу. Только для одной явно
   непокрытой самостоятельной части допустим ровно один уточняющий поиск с
   `limit=5`; максимум — два поиска на библиотеку. Не уточняй ради оформления
   или метаданных. Неполный фрагмент не разрешает выдумывать недостающие условия.
5. Только после реальной ошибки прямого вызова один раз вызови `list_libraries`.
   В read-only подключении нет `fetch_url`; не переходи к административному
   подключению или внешним страницам. При недоступности MCP сообщи об этом.

## Ответ

1. Начни с прямого ответа в одном-трёх предложениях без заголовка. Используй
   только подтверждённые факты; если ключевое положение не найдено, скажи это
   сразу, без предполагаемого ответа.
2. Добавь `## По документации` и последовательные пункты `### 1.`, `### 2.`.
   Разделяй подтверждённые и непокрытые части. Сохраняй существенные условия
   и порядок действий; рекомендации включай только при подтверждении источником.
3. После каждого подтверждённого пункта добавь ровно одну строку:
   `[Источник] {Book}; {Breadcrumb}; <{публичный URL}>`.
   Название, раздел и URL бери из результата. Если публичного URL нет, опусти
   его. Несколько полных источников разделяй ` | ` после одного `[Источник]`.
4. Для непокрытой части напиши `Подтверждение не найдено.` без выдуманного
   источника. Техническую ошибку или несовместимость версии оформи так же.
5. Последней строкой перечисли реально использованные при поиске библиотеки:
   `[Использованы библиотеки: onec_erp, onec_erp_implementation]`.
   Если использована одна книга, укажи только её; если поиска не было —
   `[Использованы библиотеки: нет]`. Уточняющий вопрос до поиска выводи без footer.

Не показывай внутренние пути, `file://`, `Snapshot date`, `undefined`, сырые
ответы MCP или трассу маршрутизации.
