# Документация PostgreSQL 18

Подтверждать сведения через read-only MCP `lib-docs`. Выполнять поиск только в
библиотеке `postgresql`.

## Границы источника

- Использовать PostgreSQL 18 из найденной версии библиотеки `postgresql`.
- Принимать как первичный источник результаты под
  `https://www.postgresql.org/docs/18/`.
- Для другой основной версии PostgreSQL прямо сообщать, что эта библиотека
  покрывает версию 18, и не переносить особенности версии 18 без оговорки.
- Сохранять различие между сервером PostgreSQL, клиентскими утилитами и
  сторонними расширениями. Для расширения использовать этот источник только
  там, где оно описано в официальной документации PostgreSQL.

## Поиск

1. Вызвать `find_version` для `library="postgresql"`: использовать указанную
   пользователем версию 18, а при отсутствии версии — ограничение `18.x`.
   Передавать найденную версию во все вызовы `search_docs`.
2. Сформулировать запрос точными терминами PostgreSQL. Включить имя команды,
   функции, параметра конфигурации, представления каталога или сообщения об
   ошибке и искомый аспект: синтаксис, блокировки, prerequisites, ограничения,
   производительность либо пример.
3. Вызвать `search_docs` с `library="postgresql"`, найденной версией и
   `limit=5`. Проверить, подтверждают ли фрагменты существенные условия ответа.
4. При неполном подтверждении уточнить запрос и повторить поиск не более двух
   раз. После трёх поисков завершить с результатом «подтверждение не найдено».
5. Вызвать `fetch_url` для URL результата только когда фрагмент обрывает нужный
   синтаксис, таблицу параметров, предупреждение или пример. Считать поиск
   завершённым, когда каждый существенный вывод поддержан найденным фрагментом
   или полной страницей.

## Диагностика

При ошибке доступности или имени библиотеки вызвать `list_libraries` один раз и
проверить наличие `postgresql`. Прямо сообщить, если MCP недоступен, версия не
найдена или библиотека ещё индексируется.

## Ответ

- Указывать найденную версию PostgreSQL и давать ссылки на использованные
  страницы.
- Сохранять точные имена SQL-команд, функций, параметров, представлений,
  режимов блокировок и допустимых значений.
- Для инструкции собирать подтверждённые prerequisites, порядок действий,
  ограничения транзакций, блокировки и эксплуатационные оговорки.
- Для SQL-примера использовать только подтверждённые синтаксис и параметры;
  явно отмечать значения, зависящие от схемы пользователя.
- Отделять собственный вывод от сведений, прямо подтверждённых документацией.
- Прямо сообщать «подтверждение не найдено», когда источник не даёт достаточного
  основания для ответа.
