# Обновление нашего fork до 3.3.0

Обновление использует образ нашего fork с сохранёнными Voyage reranking,
publication metadata, Source Artifacts, MCPB и отдельным Claude OAuth gateway.
Node остаётся в ветке 22. Ключи embedding/Voyage получает только worker.

## Изменения базы

Штатный runner применяет новые миграции 017–019: display name библиотек,
преобразование JSON embeddings в float32 BLOB и обслуживание индексов.
Наша `015-add-page-publication-metadata.sql` сохраняет полное имя и историю.
Идентификаторы страниц, документов и векторов сохраняются. После миграций
runner выполняет VACUUM; для большого индекса готовность может занять несколько
минут. Не запускайте второй worker на том же томе.

Перед переключением необходимы согласованный SQLite backup, проверка
`integrity_check`, хеши содержимого и векторов, прежний образ и прежний Compose.
На копии индекса сравниваются исходные столбцы и нормализованные float32-векторы,
количества строк и publication metadata. Формат embeddings меняется, поэтому
побайтовый хеш всего SQLite-файла после обновления будет другим.

## Переключение

1. Проверить отсутствие выполняющихся/ожидающих задач.
2. Остановить четыре основных сервиса, сохранив отдельный OAuth gateway.
3. Повторно убедиться, что контрольные данные совпадают с проверенным снимком;
   при изменениях создать свежий финальный backup.
4. Заменить только pinned image у worker, web, mcp-read и mcp-admin. Сохранить
   environment, тома, artifact subpath и подключения к worker.
5. Проверить `docker compose config --quiet`, запустить worker и дождаться
   завершения миграций. Затем запустить три coordinator-сервиса.
6. Проверить MCP initialize, точный состав read-only инструментов, 40-query
   benchmark, публикационные поля, артефакты, web HTTP/WebSocket и OAuth.

На worker остаются `DOCS_MCP_SEARCH_RERANKER_ENABLED=true`,
`DOCS_MCP_SEARCH_RERANKER_MODEL=rerank-3-lite` и лимит 30 кандидатов.
В 3.3.0 создание локальных сервисов перенесено в `openBackend`; наш factory
подключает reranker и в этой точке запуска.

## Совместимость MCP

К существующим read-only инструментам добавлены `list_pages` и `read_page`.
`fetch_url` и все изменяющие инструменты остаются вне read-only MCP.
Локальное desktop-расширение сохраняет прежний минимальный набор из трёх
инструментов. MCP SDK 1 сохраняется для уже существующих desktop-мостов;
основной HTTP сервер использует SDK 2 и поддерживает legacy handshake.

Встроенный OAuth upstream заменён JWT-проверкой. Наши статические Bearer/Basic
listener остаются защищены Apache, встроенный auth на них выключен. Отдельный
Claude OAuth gateway сохраняет свою конфигурацию и хранилище. Имена внешнего
reverse proxy должны быть разрешены через существующий public origin/URL
или явный `server.allowedOrigins`; запрещено отключать проверку для всех hosts.
Переменная `DOCS_MCP_SERVER_ALLOWED_ORIGINS` содержит JSON-массив строк,
например `["https://docs.example.com"]`. Список через запятую не принимается.

## Откат

Из-за нового формата и ограничений таблицы libraries откат включает базу.
Сначала остановить все writers. Проверить SHA256 сохранённого backup, скопировать
его в новый том с владельцем uid 1000 и восстановить прежний Compose/образ.
Текущий том сохранить для разбора. Не подключать к восстановленному файлу старые
WAL/SHM. Артефакты остаются в исходном каталоге и подключаются read-only.
До возврата пользователей проверить поиск, артефакты, web и OAuth.

`rollback.py` сверяет снимок, исходный Compose и worker environment перед
действием. Без `--apply` он только проверяет готовность. С `--apply` создаёт
новый том из снимка и возвращает прежний Compose; текущий том сохраняется.
После отката требуется функциональная приёмка MCP, web и OAuth.

```sh
python3 rollback.py "$DEPLOYMENT_DIR" "$RELEASE_DIR"
python3 rollback.py "$DEPLOYMENT_DIR" "$RELEASE_DIR" --apply
```
