# Исправление прямого доступа к веб-интерфейсу

Проверка 19 октября 2026 года после обновления до 3.3.0.

## Причина

Первое правило `ufw-user-input` выполняло DROP для всего TCP-диапазона
6100–6999. Веб-порт 6280 входит в этот диапазон. Разрешение TCP для текущего
доверенного клиентского адреса находилось ниже, на позиции 28, и не достигалось.
В `ufw status numbered` запрещающее правило также было первым.

Прямая проверка с рабочей станции дважды воспроизвела тайм-аут HTTP. Локальный
TCP connect выглядел успешным: трафик проходит через Throne TUN. Захват на
сервере показал входящие SYN от того же адреса, с которого установлена доверенная
SSH-сессия, и отсутствие SYN-ACK. Apache слушал внешний порт 6280 и локально
возвращал 401; блокировки текущего адреса в fail2ban не было. Это установило
причину до изменения правил. Прежняя проверка только наличия разрешающей
строки не учитывала порядок правил и дала неполную картину.

## Исправление

Перед существующим запретом добавлено ровно одно IPv4-разрешение: TCP 6280
только с адреса текущего доверенного подключения, маска /32. Остальные правила
сохранили содержимое и порядок, правила IPv6 не изменились. Общий запрет
6100–6999 остаётся на месте. Apache, Docker, данные библиотеки, конфигурация
reranker и аутентификация не менялись.

Защищённый каталог `rollback/web-direct-20261019T204849Z` относительно корня
развёртывания содержит исходные UFW-файлы, эффективные IPv4-правила,
контрольные суммы и состояние изменения. `rollback.py` находит единственное
правило по комментарию UFW; без `--apply` проверяет готовность, с `--apply`
удаляет только его. Проверка готовности прошла. Полный firewall не сбрасывается.

## Проверка без туннеля

Один и тот же HTTP-сценарий до изменения завершался тайм-аутом, после изменения
прошёл для настроенного адреса сервера и адреса MCP: HTTP 401 без credentials,
затем аутентифицированный HTTP 200, версия 3.3.0, worker connected. Проверки
заняли 626 и 911 мс вместо прежнего четырёхсекундного тайм-аута.

Браузер напрямую открыл веб-интерфейс: версия 3.3.0 отображается, JavaScript
errors 0, failed requests 0, HTTP errors 0. WebSocket открылся и получил кадр.
System health подтвердил подключение worker и размерность embeddings 1024.
SSH-туннель не используется. Пароль по-прежнему обязателен.

Read-only и admin MCP повторно выполнили поиск. Репозиторные lint, typecheck
с удалённым incremental cache и полный набор тестов прошли: 182 test files,
3272 tests; 3 skips и 6 todo. Код приложения и production image не менялись.

Сетевую проверку воспроизводят защищённые локальные сценарии `repro.mjs` и
`direct-ui.mjs` в каталоге диагностики `~/.cache/docs-web-direct`. Они читают
существующие параметры из `.secrets.local.env`, не печатают адреса и credentials
и сохраняют только статусы, счётчики и результаты проверок.
