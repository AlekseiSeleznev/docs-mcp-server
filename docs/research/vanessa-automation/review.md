# Отбор документации Vanessa Automation для библиотеки 1С

Дата проверки: 2026-10-01. Источник: [docs в ветке develop](https://github.com/Pr-Mex/vanessa-automation/tree/develop/docs).
Зафиксированный commit: `a2d584ced20332e7174abf94770c2dd986845a2a`.


Реализация и окончательный состав снимка от 2026-10-02 описаны в [acceptance.md](acceptance.md).
Этот файл сохраняет исходные решения инвентаризации.

## Решение

Создать отдельную библиотеку `onec_dev_vanessa_automation` для написания и запуска автотестов 1С. В первый набор включить документацию по Gherkin, клиентам тестирования, данным, собственным шагам, диагностике, CI, VAExtension и MCP Vanessa. Автодокументирование и создание видео оставить за пределами первого набора.

Это предложение отбора. Серверный индекс, установленные скиллы и каталоги не изменены. `exclude` означает исключение из будущего поискового набора, а не удаление из upstream. Решение о включении не означает проверку работоспособности описанных функций на установленной Vanessa.

- Практические уроки главы 16: подготовка данных, несколько баз, асинхронные шаги и переиспользование сценариев.

## Что исключить или отложить

Исключить старые редакции справки, большой `Changelog.md`, сценарии видеоуроков `VSL`, изображения как самостоятельные документы, оглавления как поисковые страницы, сравнение с ADD, интерактивное обучение, автовидео, озвучивание и малополезные уроки про оформление редактора.

Исключить `AI/examples/**`: это примеры конкретных проектов, управляющие промпты, правила, чеклисты и память. В них описаны действия агентов; помещение этих текстов в справочную выдачу будет смешивать знания о Vanessa с инструкциями чужого рабочего процесса.

`RAT/RAT.MD` и `RevertingDataChanges/ИнформацияОСистемеОтката.MD` — короткие описания со ссылками на отдельные продукты. Они не заменяют документацию этих продуктов; при потребности их следует изучать и подключать отдельно.

Отложить мобильное тестирование, сборку single-обработки, старые KnownProblems, правила доработки VA в режиме совместимости 8.2 и пример автодокументирования. Это не бесполезные материалы, но они требуют отдельного контекста или проверки актуальности.

## Подготовка к индексации

174 из 175 файлов последней справки содержат изображения. Текст уроков нередко ссылается на показанный пример, который доступен только на скриншоте. Поэтому нельзя просто удалить картинки и считать текст полноценным справочником.

Для выбранных уроков:

1. Добавить понятный заголовок из оглавления, главу и редакцию справки.
2. Убрать приветствия, завершения урока, повторяющиеся предложения открыть учебную Vanessa и служебную нумерацию только вне кода.
3. Сохранить смысловой текст, код, таблицы и условия применимости.
4. Проверить, понятен ли пример без изображения. Если нет — получить текст из исходного сценария урока либо проверить изображение; до этого пометить неполноту.
5. Сохранить исходный путь, commit и публичную ссылку, чтобы поисковый ответ ссылался на upstream.
6. Сохранить BSD-3-Clause notice и условия лицензии в пакете подготовленного материала. [Лицензия](https://github.com/Pr-Mex/vanessa-automation/blob/a2d584ced20332e7174abf94770c2dd986845a2a/LICENSE).

В текущем `docs-mcp-server` GitHub-стратегия распознаёт расширения без учёта регистра и фильтрует пути через `includePatterns`/`excludePatterns`. Отдельного изменения поддержки `.MD` не требуется. Для файлов, которым нужна редактура, предпочтителен подготовленный локальный набор с сохранёнными ссылками на источники; фильтры путей не умеют вырезать разделы смешанной страницы.

В `docs` нет полного справочника сигнатур всех стандартных шагов. Глава 4 объясняет работу с деревом известных шагов. Для точной генерации feature-файлов понадобится дополнительный источник: каталог шагов целевой установленной VA или соответствующие исходники `lib` в той же версии. Этот источник в рамках текущего отбора не изучался.

## Как подключить к lib-1c-dev

В текущем установленном `references/libraries.yaml` и каталоге репозитория запись Vanessa отсутствует. После загрузки и проверки поиска добавить запись `onec_dev_vanessa_automation`:

- Название: Vanessa Automation — автотестирование 1С.
- Псевдонимы: Vanessa Automation, Vanessa-Automation, VA, VAExtension.
- Темы: Gherkin, feature-файлы, клиент/менеджер тестирования, собственные шаги, тестовые данные, дымовые тесты, CI, Allure, MCP Vanessa.
- Версия: дата снимка с `version_kind: snapshot`; отдельно фиксировать commit источника и редакцию справки `1.2.043.1`. Материалы из develop вне MainHelp не следует объявлять документацией строго выпущенной версии `1.2.043.1`.

В скилле добавить маршрутизацию по явному названию Vanessa и по задаче написания/запуска её тестов. Для подтверждения платформенных API при необходимости обращаться также к книге платформы. Поисковая документация описывает MCP Vanessa; подключение и вызов этих инструментов остаются отдельной задачей.

Заменить привязку формата источника к «ITS URL» на общий публичный URL источника: для этой библиотеки нужны ссылки GitHub. Сохранить прежний формат ответа, ограничения поисков и требование подтверждать точные шаги. Не добавлять техническое имя библиотеки в установленный каталог до её реального появления в индексе.

## Проверка перед загрузкой

Проверить поиск на нескольких самостоятельных задачах: экспортный сценарий с параметрами; переменная на сервере; запуск по VAParams; статус ошибки для CI; ожидание фонового задания через VAExtension; диагностика расхождения таблицы; настройка MCP и подбор шага.

Ожидаемый результат: источник из выбранного набора, полный текст необходимого примера, подходящая версия, отсутствие старой справки и промптов в выдаче. До этих проверок готовность библиотеки не подтверждена.
