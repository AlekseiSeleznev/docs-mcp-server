Обновление и приёмка начаты 19 октября 2026 года.

Исходный fork: `0bd77903cef59dde5361fb288c5d265dbf5961c6`.
Upstream: `v3.3.0`, `4cb4390b20a86a472ec4d6d6d45490adfdb2ba35`.
Код production-образа: `500f162e6392bf1a26232e338493eed9a3d4f10c`.
Образ: `ghcr.io/alekseiseleznev/docs-mcp-server@sha256:22c19ebeb053d9eff09e95a86511166e406d23d94313225c6632ae0a210c6cd8`.

## Сохранённые доработки

Сохранены Voyage reranking, fail-open и circuit breaker, dense-recall floor,
publication metadata, SAP Source Artifacts и MCP resources, минимальный MCPB,
hosted desktop bridge, отдельный Claude OAuth, библиотечные навыки и их updater.
Новый `openBackend` вызывает наш factory, подключающий reranker. В основном
read-only MCP семь инструментов: `find_version`, `get_source_artifact`,
`list_libraries`, `list_pages`, `list_source_artifacts`, `read_page`, `search_docs`.
Произвольный `fetch_url` и операции записи в этот набор не входят. Минимальный
MCPB сохраняет прежние три инструмента и SDK 1; основной MCP использует SDK 2.

В SQL поиска сохранены dense-recall floor и publication metadata, добавлены
исправления и стабильный порядок upstream. Ошибка соединения с worker
по-прежнему не раскрывает его приватный адрес. Provider credentials получает
только worker. Node остаётся в ветке 22.

## Данные и восстановление

До обновления на сервере: 120 библиотек, 120 версий, 35 983 страницы,
187 494 фрагмента и вектора, 128 страниц с publication metadata.
Embedding model BGE-M3, размерность 1024. Включён `rerank-3-lite`, 30 кандидатов.
Сохранён согласованный снимок SQLite размером 6 621 130 752 байта.
SHA256: `bcf8504f5028f000644291a6eaeb75a82ea865c991bad448b4adad56d9e488c5`.

Миграции 017–019 добавляют display name, переводят embeddings из JSON в float32
BLOB и меняют индексы. Наша миграция `015-add-page-publication-metadata.sql`
сохраняет имя и историю. Для сравнения исходных и новых данных вычисляются
хеши исходных столбцов libraries/versions, всех страниц, содержимого и метаданных
документов, канонических float32 embeddings и записей `documents_vec`.
Проверяются integrity и внешние ключи. Изменение формата базы исключает простой
возврат старого writer к мигрированной базе.

Проверен реальный откат: снимок восстановлен в отдельный том, его SHA256
совпал, прежний образ 3.2.1 запущен с четырьмя healthy сервисами. После возврата
сохранились 120 библиотек и 187 494 документа. Рабочий том при этом не менялся.
Скрипт отката сохраняет мигрированный том и создаёт новый из проверенного backup.

Защищённый серверный каталог `rollback/upstream-3.3.0-20261019` относительно
корня развёртывания хранит backup, исходный Compose, хеши environment,
результаты проверки и скрипт отката. Порядок:
[deploy/upgrades/3.3.0/README.md](../../deploy/upgrades/3.3.0/README.md).

На изолированной копии рабочего индекса миграции и последующее уплотнение

Рабочий сервер переключён на pinned image за 535,71 секунды, включая

Повторная рабочая приёмка дала те же метрики 40 запросов, прошли дополнительные

Внешние read-only/admin MCP отвергают запрос без авторизации (401), выполняют

DCR, PKCE, MCP initialize, read-only tools и search_docs.

Веб-интерфейс проверен браузером через SSH-туннель к действующему Apache:
Basic auth, HTTP 401 без credentials, версия 3.3.0, отсутствие ошибок JS/загрузки,
подключённый worker с размерностью 1024, WebSocket с двумя полученными кадрами.

разрешается, обращения к обнаруженному порту по настроенным адресам сервера
заканчиваются тайм-аутом. Локально на сервере Apache отвечает 401. UFW включён,
его правила разрешают текущий SSH source для TCP 6280 и 6281; точная внешняя
сетевая причина на этапе обновления не установлена. Firewall и Apache-конфигурация
на этом этапе не менялись. Последующая проверка выявила запрещающее правило,
которое стояло перед разрешениями. Прямой доступ исправлен и проверен без
туннеля; см. [разбор и приёмку исправления](direct-web-access-fix-2026-10-19.md).
